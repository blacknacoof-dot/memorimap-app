[P0] 직접 URL 접근 차단 및 권한 분기

[Steps]
1. 로그아웃 상태에서 `/facility-admin`으로 직접 진입한다.
2. 로그아웃 상태에서 `/super-admin`으로 직접 진입한다.
3. 일반 user 계정으로 로그인한 뒤 동일 URL을 다시 입력한다.
4. facility_admin, super_admin 계정으로 각각 진입한다.

[Expected - UI]
- guest는 로그인 유도 또는 접근 차단 화면이 보여야 한다.
- 일반 user는 관리자 화면이 노출되면 안 된다.
- 권한이 있는 관리자만 해당 대시보드가 열린다.

[DB Check - SQL]
```sql
select user_id, role
from public.profiles
where user_id in ('<USER_UUID>');
```

[FAIL Case]
- guest가 관리자 화면에 진입하면 실패.
- 일반 user가 관리자 API를 호출해도 데이터가 노출되면 실패.

[Data Integrity Check]
- profiles.role 값이 실제 접근 권한과 일치해야 한다.
- 관리자 식별자가 비어 있으면 안 된다.

[Permission Check]
- guest: 차단
- user: 차단
- admin: 허용

- 화면이 빈 상태로 깨지면 안 된다.


[DB Check - SQL]
```sql

       fs.facility_id,
       fs.facility_id_uuid,
       fs.facility_id_bigint,
       fs.plan_id,
       fs.status,
       sp.id as subscription_plan_id,
       sp.name_en,
       sp.name_ko
from public.facility_subscriptions fs
left join public.subscription_plans sp
  on sp.id::text = fs.plan_id
where fs.facility_id_uuid = '<FACILITY_UUID>'
   or fs.facility_id_bigint = '<FACILITY_BIGINT>';

from public.subscription_payments
where facility_subscription_id = '<SUBSCRIPTION_ID>'
order by created_at desc;
```

1. sangjo_hq_admin으로 로그인한다.
2. 상조 대시보드를 연다.
3. commission simulator 값을 바꾼다.
4. revenue tab과 upgrade banner를 확인한다.

[Expected - UI]
- 대시보드 요약이 보여야 한다.
- 시뮬레이터 값이 즉시 반영되어야 한다.
- 업그레이드 배너와 비교 영역이 정상 표시되어야 한다.

[DB Check - SQL]
```sql
select id, user_id, company_name, role
from public.sangjo_hq_admins
where user_id = '<USER_UUID>';

select id, facility_id_uuid, plan_id, status, updated_at
from public.facility_subscriptions
where plan_id like 'sj_%'
order by updated_at desc;
```

[FAIL Case]
- 대시보드 숫자가 DB와 다르면 실패.
- 시뮬레이터가 plan_id 정규화와 다르게 계산되면 실패.

[Data Integrity Check]
- plan_id는 canonical 값이어야 한다.
- 수익/수수료 계산이 동일 기준이어야 한다.

[Permission Check]
- guest/user: 불가
- facility_admin: 일부 조회만 허용
- sangjo_hq_admin: 가능

[P1] 관리자 공지 / 로그 / 시스템 설정

[Steps]
1. super_admin으로 로그인한다.
2. 공지 작성 화면을 연다.
3. 공지를 저장한다.
4. 로그와 시스템 설정 화면을 연다.

[Expected - UI]
- 공지가 목록에 즉시 반영되어야 한다.
- 로그와 설정 화면이 정상 열려야 한다.

[DB Check - SQL]
```sql
select id, title, content, created_by, created_at
from public.notices
order by created_at desc;

select id, user_id, action, resource_type, resource_id, created_at
from public.audit_logs
order by created_at desc
limit 20;
```

[FAIL Case]
- guest/user가 공지 작성 가능하면 실패.
- 로그가 비어 있는데 저장 성공 처리되면 실패.

[Data Integrity Check]
- created_by와 실제 작성자 권한이 일치해야 한다.
- 로그 row가 누락되면 안 된다.

[Permission Check]
- guest/user: 불가
- admin/super_admin: 허용 범위 내 가능

[P1] 리뷰 작성 / 조회

[Steps]
1. 시설 상세에서 리뷰 작성으로 이동한다.
2. 평점과 내용을 입력한다.
3. 저장 후 목록에 반영되는지 확인한다.

[Expected - UI]
- 리뷰가 목록에 추가되어야 한다.
- 작성자 정보가 표시되어야 한다.

[DB Check - SQL]
```sql
select id, user_id, facility_id, rating, created_at
from public.reviews
where user_id = '<USER_UUID>'
order by created_at desc;
```

[FAIL Case]
- 비로그인 상태에서 작성되면 실패.
- rating 범위를 벗어나면 저장되면 안 된다.

[Data Integrity Check]
- review.user_id와 facility_id가 정확히 연결되어야 한다.
- 중복 제출이 허용되지 않는 규칙이면 중복 row가 없어야 한다.

[Permission Check]
- guest: 불가
- user: 가능
- admin: 조회 가능, 일반 작성은 정책에 따름
